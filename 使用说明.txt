============================================================
  cme-uf8-router — CME UF8 (一代) MIDI 路由器 · 使用说明
============================================================
版本 0.1.14 · universal2 (x86_64 + arm64,Intel 与 M 芯片通用)

【这是什么】
把 CME UF8 键盘(含非标准信号的型号)接进 Mac 的 MIDI 路由器。
- 输入源、输出目标都由你自己在下拉里选(不写死 USB 口)
- 支持串联:实体键盘从别的 MIDI 接口进来也能用
- 协议自动识别:CME 的 0x0F 私有帧 或 标准 MIDI 流,自动判断,也可手动指定
- 两种接法都支持(菜单里切换):琴经 U2MIDI Pro 等接口进来 / 直接插 USB 线(0.1.13 新增)

【安装(在你自己的电脑上)】
1. 打开 DMG,把 cme-uf8-router.app 拖入「应用程序」
2. 双击启动(菜单栏出现 UF8 图标)
3. 首次启动若提示「无法验证开发者」:右键 App → 打开 → 确认(ad-hoc 签名属正常)
4. 在菜单里选【输入源】= 键盘进 Mac 的口,【输出目标】= DAW 或虚拟入口

【换到别的电脑使用】
- 直接拷 DMG(App 是 universal2,Intel / M 芯片都跑)
- 新电脑同样:打开 DMG → 拖入应用程序 → 打开
- 无需安装任何额外框架或驱动(纯系统 CoreMIDI)

【关于「找不到 MIDI 设备」(0.1.2 已修)】
菜单里的【输入源】列出的是 macOS CoreMIDI 当前在线的所有源,格式:
    <端口名> — <设备名>        例:Port 1 — U2MIDI Pro
- 任何 CoreMIDI 源都能选进来,不需要额外的「桥」或虚拟端口。
- 列出来的是「接口/设备」,不是琴的名字:UF8 走 5-pin 接 U2MIDI Pro 时,
  会显示成 Port 1 — U2MIDI Pro,这就是你的琴。
- 列表为空 = 系统层面就没看到设备:先确认接口插好、驱动在(系统信息 → USB),
  再点【刷新设备】。
- 只插了一个源时会自动选中,不用手点。

【菜单说明】

【常见问题】
- 输入/输出列表是空的?
  确认键盘已开机并插好;点「刷新设备」。若用的是接口盒/DIN,应看到对应接口名。
- 苹果芯片提示无法打开?
  App 已 ad-hoc 签名 + universal;首次请在 App 上右键→打开 放行。
- 和旧 cme-uf8-bridge 的区别?
  桥是「找 USB→建虚拟源」固定写法;本 App 是「任意源 → 任意目标」可配置路由器,
  且补全了 CME 0x0F 私有协议的支持(transport 键/特殊信号不再丢)。
- transport 键(PLAY/STOP/REC 等)发的不是标准 MIDI?
  协议模式选「自动识别」即可;这些键默认映射为 CC 114–119(见复刻规格书.md §3),
  可在 ~/Library/Application Support/cme-uf8-router/midi-map.plist 调整。


【transport 键(播放/停止/录音/快进/快退)怎么用 —— Mackie Control 方案】

证据(两条,互相印证):
  1) 2006 年原驱动 readme.txt 写明(PС v1.0.5 / MAC v1.1.0):
       RTZ→CC115  REW→CC116  FF→CC117  REC→CC114  STOP→CC118  PLAY→CC119
       M.VOLUME 推子 → CC#7,CH1
  2) 真机抓包(本机 U2MIDI Pro 进 Mac)显示琴本身发的是 **标准 MMC**,
     不是 CC —— 也就是说 CC114-119 是当年驱动在电脑侧做的翻译层,
     和本 App 现在做的事一样。
       REC 按下  F0 7F 00 06 06 F7 (Record Strobe)
       REC 松开  F0 7F 00 06 07 F7 (Record Exit)
       STOP      FC   (系统实时 Stop)
       PLAY      FA   (系统实时 Start)
       REW/FF/RTZ  F2 lsb msb (SPP,倒退/前进/归零)
     Linux 内核只处理 CME 的 0x0F 私有帧,没有这张映射表,所以别处查不到。

菜单【transport 键】里三选一(单选,互斥):

A. 用 Mackie Control 发 transport(推荐,Logic/Cubase/Reaper/Ableton 全认)
   1. DAW 里装控制表面:Mackie Control
      (Logic:控制表面设定 → 安装 → 生产企业 Mackie Designs → 型号 Mackie Control)
      输入选 CME UF8 Router MCU,输出也选 CME UF8 Router MCU
   2. 按琴上的 PLAY/STOP/REC/FF/REW 就能控制走带
   对应关系(MCU 是 Note On CH1):
       PLAY→0x5E  STOP→0x5D  REC→0x5F
       快进/快退/回到起点 → Jog 轮 CC#60(+1 / -1),一下走一小节
   为什么快进快退用 Jog 而不用 MCU 的 FF/REW 按键:
       实测 Logic 只认 MCU 的「按下」,不认「松开」——按住就一路飞,
       松不开(82ms / 157ms / 253ms / 3 秒全试过,`90 xx 00` 和 `80 xx 00` 都无效)。
       Jog 轮是「转一格走一格」,天生没有按下/松开状态机,一次一小节,稳。
   App 会自动回应 MCU 的握手查询(F0 00 00 66 14 00 F7 → 00 66 14 01),DAW 才认。

B. 翻成 CC114-119(菜单里选「翻成 CC114-119」)
   在 Logic 里 ⌘K 控制器分配 → 学习 → 按琴上的键 → 指定参数。
   这个模式下 MMC 原件被替换,不会双触发。
   注意:走带 CC 由白名单里「走带: CC#114-119 + CC#60 Jog」那一项单独管,
         整类「控制器 CC」关掉不会影响它。

C. 原样转发 MMC(F0 7F …,不做任何翻译)
   给认原生 MMC 的软件用(Logic 设 MMC 从机 / Cubase 认 MMC)。
   注意 MMC 的录音键是「开关」语义:按一次 Record Strobe(06 06),
   再按一次 Record Exit(06 07),这是标准 MMC 行为,不是重复发包。

【虚拟 MIDI 输出(给 DAW 用)】
App 自己建一个虚拟 MIDI 源,名字就叫 "CME UF8 Router":
- 打开 Logic / Ableton / Cubase / Reaper / Sibelius…
- 在它的 MIDI 输入里选 "CME UF8 Router",弹琴就有声音
- 不用装 IAC,不用建聚合设备,不用桥
菜单【输出目标】默认就选中这一项;选成真实硬件端口才会把消息送回设备。

【两套输出怎么分工(重要)】
- 平时只有一个虚拟口:CME UF8 Router  ← 弹奏(音符/弯音/CC)走这里,DAW 的音轨输入选它
- 只有你勾了「transport 键 → 用 Mackie Control 发 transport」,才会额外出现
  CME UF8 Router MCU  ← 走带键走这里,Logic 里装 Mackie Control 表面时输入/输出都选它
  不勾 = 这个口不存在,不会占用 DAW 的端口列表。
  transport 键只走 MCU 口,弹奏照旧;两者互不干扰,弹 B4~D#5 也不会误触走带。

【0.1.13 两种输入方式(新增 USB 直连)】
琴的 USB 口一直有个怪毛病:它把自己报成「串口设备」(CDC),macOS 于是不给它装
MIDI 驱动 —— 所以「音频 MIDI 设置」里永远看不到它,老驱动当年也是靠自己读 USB 才通的。

0.1.13 把这个能力做进 App 了,两条路随便选:

  A. MIDI 端口(U2MIDI Pro 转接头,老办法)
     菜单【输入源】→ 选 "Port 1 — U2MIDI Pro"
     优点:稳,系统层就认识它;缺点:多一个盒子

  B. USB 直连(不用转接头)
     菜单【输入源】→ 选 "用 USB 直连琴(不用转接头)"
     直接把琴的 USB 方口插到 Mac,App 自己读(0x82 端点)
     选完这一项就生效,配置会记住,下次启动自动还是它

两条路的差别(实测,别期待 B 解决走带键问题):
  · 走带键在两路上发的东西一模一样(三个键都是 SPP、REC 是 MMC、STOP=FC、PLAY=FA),
    所以 Jog 轮那套方案照旧,`|<<` 和 `<<` 在 USB 上也分不开
  · USB 直连会多出 77 条/秒的时钟和 4 条/秒的心跳包(琴自己一直发),这属于正常
  · 有些 DAW 会把这股时钟当成速度(显示 77 BPM 之类的怪数字);
    烦的话到【放行(白名单)】里把「时钟 F8」和「Active Sensing」取消勾选,不影响弹奏
  · 重要:**时钟不是噪音**。琴上的走带灯/录音灯就是跟着时钟闪的,而且有些 DAW
    靠它对齐 tempo。除非真的被它搞乱速度显示,否则**建议保持「时钟 F8」勾选**
  · USB 直连偶尔会被别的程序抢着(Chrome 的 WebUSB 页面会占住这台琴);
    真被占了,菜单里会显示「打开 USB 接口失败」,把那个网页关掉再切一次即可

想切回端口:菜单【输入源】里选任何一个 MIDI 端口,就是 A 路。

【0.1.14 录音键按第二次 = 停止】
- 琴的录音键是开关:第一次发 MMC 的 Record Strobe(06 06),再按一次发
  Record Exit(06 07)。以前后者被当噪音丢掉,所以你按第二次没反应。
- 现在改成把 Record Exit 翻成「停止」:按一次进录音,再按一次停(录音结束、走带停)。
- 为什么不能翻成「录音键再按一次」:实测 Logic 的录音键**只进不出**,
  连鼠标点它自己要两下才停都一样 —— 在 Logic 里再按录音键不会停止录音,必须用停止。
- 走带三选一里的 B(CC114-119)和 C(原样 MMC)模式不受影响,原样转发。

【0.1.13 白名单 / 走带三选一 / USB 直连】
- 【过滤器】改名【放行(白名单)】:勾着才进 DAW。默认全勾(= 和以前一样直通),
  不勾的东西一律被挡。个人常用的四个 CC 号单独列出来(CC#1/#2/#7/#64),
  加上「走带 CC#114-119 + CC#60 Jog」,都可以单独开关。
- 走带三选一改成单选(互斥):Mackie Control / 翻成 CC114-119 / 原样转发 MMC。
  以前是两个独立勾,会出现「两个都勾但只有一个生效」的骗人状态。
- 输入源新增「用 USB 直连琴」:琴的 USB 口不是标准 MIDI 设备(接口类上报的是 CDC),
  系统看不见它,App 现在自己直读 0x82 端点。插拔后会自动重连;
  打不开会立刻退回端口输入并在日志里写明原因(多半是浏览器 WebUSB 占着)。
- 老配置文件会自动补齐新键(白名单六项 + 五个单独 CC + 输入方式),不会丢设置。

【0.1.12 走带键改用 Jog 轮(一小节一格)】
- 实测发现的硬事实:Logic 的 Mackie Control 收到 FF/REW 的「按下」就开始连续快进,
  而它对我们随后发的「松开」完全不理会 —— 82ms / 157ms / 253ms / 按住 3 秒,
  四种时长、两种写法(note-on 力度 0 与真 note-off)全都停不下来,只有 STOP 能停。
  用鼠标点 Logic 自己的 ⏩ 是一下一下地走,说明不是 Logic 的设计问题,是按键这条
  路径本身在 DAW 里就不成立(它的表现是「按住式」语义)。
- 现在 |<< / << 发 Jog 轮逆时针(B0 3C 41),>> 发 Jog 轮顺时针(B0 3C 01),
  一格 = 一小节,连按多下就多走几小节,没有「按住/松开」的状态机。
- STOP / PLAY / REC 仍然是 MCU 的走带键,不受影响。
- 自检同步改成断言 Jog 报文(b0 3c 01 / b0 3c 41)。

【0.1.11 修了什么】
- 修一个隐蔽 bug:>> (快进)在 App 刚启动后按第一次没反应。
  原因是同一条 SPP 报文被算了两遍,第二次算的时候位置基准已经更新,
  方向判断成了 0,事件被丢掉。现在 key 只算一次。
- 自检基线固定(不再受你当前配置影响),verify.sh 六项全绿。
- 跑自检前如果 App 正在运行,会直接提示并被拦下(以前会抢端口,
  抢完 Logic 里的控制表面就整片失灵)。


【0.1.10 走带键改成「一小节」】
- 现象:按 |<< 会一直往回滚(像按住了不放),>> 干脆没反应。
- 原因:按下和松开几乎同一时刻发出去,Logic 把「松开」当成抖动丢了,
  于是按键在它看来一直是被按住的 —— 表现就是连续快退,并且下一个键被堵住。
- 修法:按下立刻发,松开故意晚 80ms 再发(走独立队列,不占主线程)。
  这样一次干脆的按键 = 走一小节,按几下走几小节;按住不放仍然是连续(靠琴自己的重发)。
- |<< 和 << 仍然发同一份数据(5-pin 线上没有按键 ID,这点无解),所以两者都是「向左一小节」。

【0.1.7 修了什么】(一次独立代码审计后修的一批问题)
- 菜单勾选态显示错:App 启动时菜单先建、配置后恢复,导致「用 Mackie Control 发 transport」
  明明在跑却不打勾。现在启动完会按真实状态重建菜单(过滤器/协议模式同理)。
- 热插拔时可能崩溃:设备变化的通知是在系统线程上来的,以前直接在那里改菜单用的数据,
  主线程正在遍历这份数据就会崩。现在通知只负责「转告主线程」,不在回调里做任何事。
- 「琴突然不响、只能重启」:设备发来一条 sysex 但结束符 F7 丢了之后,后面的音符会被
  一直当成 sysex 吞掉。现在有 1 秒超时 + 8KB 上限 + 遇到新的状态字节就丢弃残包。
- 热插拔后音符可能发到别的设备:以前按「系统里的序号」记输出目标,设备插拔一次序号就变了。
  现在记的是设备端点的唯一引用。
- 启动半途失败会留下一个「没人喂数据」的虚拟端口:现在失败一律完整撤掉。
- 演奏时卡顿/掉音:原始报文抓包以前默认开着、而且在 MIDI 实时线程上同步写文件。
  现在默认关、写到后台队列、单文件 8MB 自动轮转,菜单里有「抓原始报文(排错用)」开关。
- 标准流设备的 running status 解析错误:会丢音符、音高错乱。已修(有自检锁住)。
- 按住走带键会每 ~250ms 反复触发一次(DAW 里播放/停止来回跳),而快速连按两次又会被吞:
  改成 0.4 秒内同一个键只算一次。
- 虚拟端口使用固定 uniqueID:Logic 的控制表面不再每次重启都掉线、要你重选端口。
- 输入源 / 输出目标 / 协议模式都会持久化;设备不在时会写一行日志说明「回退到默认」。
- 日志窗口没打开时也保留最近 500 行,打开后自动回填(以前启动失败的原因根本看不到)。
- MMC 的 Record Exit 不再被当成「停止」;MMC→CC 翻译改成成对发 127/0(DAW 才认第二次按)。
- 单实例锁:重复打开不会出现两个实例抢同一个端口、每个音符发两遍。
- 新增 verify.sh:一条命令跑完 6 项自检(协议/菜单/动作/路由/退出撤端口/单实例)。

【琴上最左两个键(|<< 和 <<)为什么一个样】
这两个键在琴内部发的是**完全相同**的 F2 00 00(Song Position Pointer,位置=0),
经 5-pin 进来后没有按键 ID,因此在电脑侧无法区分——这是硬件路径的限制。
当年原厂驱动能分成 CC115/CC116,是因为它走 UF8 自己的 USB 口 + CME 私有帧(帧里带按键 ID)。
现在两个键都发 MCU 的 REWIND;要「回到开头」用 Logic 自带的 Return 键。

【按走带键时乐器跟着响(琴声)】
MCU 的按键本身就是音符(REWIND=Note 91、STOP=93、PLAY=94、RECORD=95,CH1),
乐器音轨和控制表面读的是同一股数据。关掉的办法:
  Logic → 设置 → MIDI → 输入,把 CME UF8 Router MCU 这一项的勾取消(只留 CME UF8 Router)。
  控制表面是直接读端口的,不受这个勾选影响。

【Logic 说控制表面离线 / 走带键没反应时】
App 重启时 MCU 端口会先消失再出现,Logic 可能把设备判成离线:
  控制表面设定 → 选中 Mackie Control → 编辑 → 输入/输出 各重选一次 CME UF8 Router MCU。
仍不行就删掉这台设备,重新「安装 → Mackie Control」建一次。

【0.1.5 修了什么】
- 勾选 Mackie Control 时 App 卡死 → 已修(拆除端口的函数误写成调用自己,无限递归)
- 强制退出列表里看不到本 App → 属「仅菜单栏 App」特性,已在使用说明里给出 pkill 办法
- MCU 端口改为按需创建:不勾选就完全不出现,不再常驻两个多余端口
- 配置文件加版本号并自愈,避免旧版把「MMC→CC 翻译」误存成关闭

【0.1.2 修了什么】
- 「退出」灰着点不动 → 已修(菜单项目标改成 NSApp)
- 输入源/输出目标菜单空白、找不到设备 → 已修(核心对象此前从未创建)
- 点菜单项勾不动、协议模式切了没反应 → 已修(同上,配置对象为空)
- 放行(白名单,0.1.13 起)默认为「全勾」(直通),不再偷偷丢 CC1/CC7/时钟
- 设备名后加「— 设备名」,并支持同名端口自动加序号

【退出 / 卡住了怎么办】
正常退出:菜单栏 UF8 图标 → 退出(菜单最后一项)。
它是「仅菜单栏」App(不占 Dock),所以 强制退出(⌥⌘esc) 列表里常常看不到它。
万一卡死,任选一种:
  1. 终端里执行:  pkill -f cme-uf8-router
  2. 打开「活动监视器」,搜索 cme,选中后点 ✕ 强制退出
  3. 再重新打开 App 即可(配置不会丢)

【配置自愈(0.1.5)】
0.1.4 及更早版本的配置文件里,MMC→CC 翻译会被 MCU 开关连带写成「关」。
0.1.5 启动时若发现是老格式配置,会自动恢复默认并重新保存(过滤器全关、MMC→CC 开)。
想彻底重来:删掉 ~/Library/Application Support/cme-uf8-router 再启动。

【自检(排查用)】

  --usb-selftest   直读琴的 USB 口 3 秒,打印收到多少包(验证 B 路通不通;琴要插着、开机)

  App 内可执行文件 --selftest        协议层自检
  App 内可执行文件 --menu-selftest   菜单项 target/action 自检(防灰显)
  App 内可执行文件 --quit-selftest   端到端验证「退出」真能终止进程
  App 内可执行文件 --action-selftest 真点菜单项(过滤器/协议/选源/退出)
  App 内可执行文件 --route-selftest  端到端路由(含 MMC→CC、MMC→MCU 按键)
  App 内可执行文件 --reset-config    配置文件恢复默认值

【卸载】
删掉 App 即可。若需清除配置:
  rm -rf ~/Library/Application\ Support/cme-uf8-router
